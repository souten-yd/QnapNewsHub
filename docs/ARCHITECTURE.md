# QnapNewsHub — AI ニュース・ナレッジ分析基盤（設計 v2・2026-11-24）

利用者の構想（2026-11-24、「これをベースにしてさらにブラッシュアップして」）を土台に、それまでの設計（`DESIGN.md`・`KNOWLEDGE.md`・`research-free-llm-batch.md`）と実装（1 段: ニュースの核・認証・下ごしらえ）をまとめ直したもの。**この文書が正**。`DESIGN.md`・`KNOWLEDGE.md` は経緯として残す（食い違えばこちら）。

## 0. 目的
日々流れてくる情報を、**時間が経つほど価値が上がる知識のデータベース**に変える。記事を保存するだけでなく、記事に含まれる技術・事実・数値・ノウハウ・ほかの技術との関係を、独立したデータとして持つ。5 つの役割を 1 つにする。

| 役割 | 中身 |
|---|---|
| News Hub | 世界中のニュース・技術情報を集める（24 時間・取りこぼさない） |
| Knowledge Hub | 事実・技術・ノウハウを長くためる（根拠・時刻・履歴つき） |
| Intelligence Hub | トレンド・イベント・変化を見つける |
| Research Hub | ControlDeck の Web 調査と、ためた知識を一緒に使う。調査の結果もためる |
| Artifact Hub | AI 生成の画像・グラフ・報告を保管する |

## 1. 役割の分け方（変えない原則）
- **QNAP（TS-253Be 相当・Celeron J3455・x86_64・16GB）= 正本**: 集める・ためる・検索する・集計する・API。ControlDeck が止まっていても、単体で集める・ためる・全文検索・読む ができる。
- **ControlDeck（R9700）= 重い分析の係**: 本文の取り出し（Trafilatura）・埋め込み（Embedding）・イベントのまとめ・要約・知識の取り出し・矛盾の検出・知識の統合・画像生成・報告。QNAP の仕事の列から仕事を借りて、結果を返す。
- ControlDeck は NAS の SQLite を直接開かない。必ず API で（切断時の破損・競合を防ぐ）。
- ControlDeck の既存の機能・API を不用意に変えない（ControlDeck 側の変更は ControlDeck の決まりで PR を通す）。

## 2. 技術の選び方（利用者の案から変えた所と理由）
| 用途 | 採用 | 備考 |
|---|---|---|
| サーバー | **Python 3.12 ＋ FastAPI**（利用者の案は Go が第一候補） | ControlDeck とニュースの核を共有でき、1 段ですでに動いている。目標（常駐 512MB 以内・待機 CPU 1% 未満）を実機で測り、満たせない所だけ Go などに置き換える（v1.0 の前に判断）。 |
| 画面 | **React ＋ TypeScript**（案は Vue 3） | ControlDeck の画面（放送局ほか 5 デザイン・取得先の管理）をそのまま使い回せる。 |
| 記事・メタデータ・知識グラフ・ジョブ | SQLite（WAL・単一の書き手） | 1 つのファイルを正本に。大きくなったら年ごとのアーカイブ。 |
| 全文検索 | SQLite FTS5 ＋ **trigram**（日本語の部分一致） | 形態素解析（Sudachi）は ControlDeck の分析の仕事で行い、語の列を索引に足す（QNAP では辞書を常駐させない）。 |
| ベクトル | ControlDeck で計算 → **INT8 で QNAP に保存** | QNAP での意味の検索は測ってから（100 万件 × 384 次元 INT8 = 384MB、総当たりで 1 秒前後の見込み。足りなければ IVF の索引）。Qdrant は常駐させない（選べる道として残す）。 |
| 大量の集計 | 集計の表（増分）。必要なら DuckDB ＋ Parquet を夜に | 常駐の主データベースにはしない。 |
| 本文 | Zstandard で圧縮した塊（データベースの中の BLOB） | 細かいファイルを何百万も作らない。 |
| グラフ・チャート | Apache ECharts（遅延読み込み） | ヒートマップ・ツリーマップ・推移。 |
| 知識の地図 | Cytoscape.js（遅延読み込み） | 選んだ点の周りから段階的に広げる（一度に全部を送らない）。 |
| 配布 | QPKG（x86_64）・Linux・PWA | サーバーの起動時に npm build をしない（build 済みを配る）。 |

## 3. データの形
| 種類 | 中身 |
|---|---|
| Article | 個々の記事・論文・公式の発表（取得先・URL・GUID・題・抜粋・日時・言語・画像・本文の圧縮の塊・本文の hash） |
| Event | 複数の記事が報じる同じ出来事（代表の記事・関わる記事・一次情報かどうか・初報の時刻） |
| Entity | モデル・会社・人・製品・技術・制度など（正規化のキー・別名・種類・初出） |
| Claim | 記事が述べる個々の事実・主張（主語の物・内容・根拠の記事・確かさ〔公式／報道／実測の報告／未確認〕・時刻） |
| Knowledge | 再利用できる技術知識・ノウハウ（知識カード。AI の部分と利用者のメモの部分を分ける） |
| Relationship | 物・知識どうしの関係（種類〔使う・対応する・置き換える・競う・一緒に出る〕・根拠・確かさ） |
| Metric | 数値（性能・速度・価格・容量・金利）と **測定の条件**（モデル・量子化・GPU・VRAM・エンジン・版・文脈の長さ・同時数） |
| Note | 利用者のメモ・考察（**分析のやり直しで上書きしない**） |
| Trend | 話題の増減・新しい話題（日ごとの集計から） |
| Artifact | AI 生成の画像・グラフ・報告（hash で重複を管理、メタデータと置き場所） |
| Research | ControlDeck の調査（テーマ・検索の条件・見た出典・確かめた事実・比較表・その時の結論・分からない点・生成物） |

- すべての派生データに **根拠（記事・調査）・時刻・分析したモデル・分析の版・入力の版** を持つ。知識は上書きせず、**時系列の変化として残す**（例: あるモデルの ROCm の対応「非対応 → 実験的 → 正式 → 一部の環境で不具合」）。
- AI の回答そのものを事実として入れない。根拠を確かめられる情報だけを知識に統合する。

## 4. 1 日 1,000 件を知識に変える（段階的に）
| 処理 | 対象 | どこで |
|---|---|---|
| 取得（RSS・Atom・一覧の巡回・GitHub・arXiv など） | 全部 | QNAP |
| URL・GUID・hash の重複の判定、SimHash の近い重複 | 全部 | QNAP |
| 語の取り出し（統計・N-gram）・言語の判定 | 全部 | QNAP（軽い CPU の処理） |
| 本文の取り出し | 取れる記事 | ControlDeck（Trafilatura） |
| 埋め込み・イベントへのまとめ（クラスタ） | 重複を除いた記事 | ControlDeck |
| 短い要約・要素の取り出し（物・主張・数値） | イベントの代表 ＋ 追加の情報のある記事 | ControlDeck（小さな LLM）／無料の外部 LLM |
| 詳しい分析・矛盾の検出・知識の統合 | 重要なイベント・新しい事実 | ControlDeck（高品質の LLM） |
| トレンド | 全部の統計 | QNAP（集計の表）・ControlDeck（トピックの分類） |

- 同じ出来事を 20 のサイトが報じても、詳しい分析は代表の 1 回。ほかの記事からは **新しい数値・異なる評価・追加の情報だけ** を取り出してイベントにまとめる。
- 優先度の低い記事も、検索できる状態で残す。
- 下ごしらえの件数: 無料の外部 LLM は 1 回 30 件（`research-free-llm-batch.md`）。ControlDeck の CPU の Gemma は 1 回 10 件。
- 1 日の分析の時間の目安（ControlDeck）: 簡易 200 件 × 300 トークン ＋ 詳細 50 件 × 1,000 トークン = 11 万トークン、40 tok/s で 0.8 時間（読み込み・埋め込み・載せ替えは別）。Radiance のように並列で伸びるエンジンでは、独立した記事の分析をまとめて流す。チャット・開発を優先し、ニュースの分析は低い優先度の裏の仕事。

## 5. 仕事の列（ジョブ）と ControlDeck の受け渡し
- QNAP が仕事を持つ: 種類（本文・埋め込み・まとめ・要約・取り出し・詳細・統合・画像）・入力の版・**重複を防ぐ ID**・**期限つきの借り（lease）**・やり直しの回数・使ったモデル・状態。
- 係（worker）が借りて返す:
  - **ControlDeck**（つながっている間。GPU・CPU）
  - **QNAP の中の「無料の外部 LLM の係」**（計算はしない。ControlDeck が既定 6 時間以上つながらないときだけ、要約・取り出しの仕事を借りる。設定で入・切。1 日 300 回・1 分 10 回の上限）
  - **QNAP の上で LLM を動かすことは、既定で切**（非力なため）。
- ControlDeck が途中で止まっても、借りの期限が切れた仕事は列に戻り、再開後に安全に続く。同じ入力の版の結果は二重に入らない。

### API（`/api/v1`）
| API | 用途 |
|---|---|
| `GET /search` | 統合の検索（全文・物・つながり・時系列・数値。ベクトルはある場合） |
| `GET /articles`・`/events`・`/knowledge`・`/graph`・`/trends`・`/metrics` | 取得 |
| `GET /changes?cursor=` | 前回からの差分（ControlDeck の同期） |
| `POST /jobs/claim`・`/jobs/complete` | 分析の仕事を借りる・結果を返す |
| `POST /knowledge/batch` | 知識をまとめて入れる |
| `POST /artifacts` | 生成物（画像・報告）を送る |
| `POST /research` | 調査の記録を送る |
| `GET /storage/status` | メモリ・DB・保存の状況・書き込みの診断 |
| `GET /health` | 稼働の状態 |
- 権限を分ける: 読み取りのトークン／仕事を返すトークン（ControlDeck）／管理者の session。

### つなぐ・鍵を渡す
- 6 桁の番号 ＋ ニュースハブの公開鍵の指紋（利用者が両方の画面で見比べる）でトークンを発行。
- OpenRouter の鍵は、利用者が「渡す」を押したときだけ、ニュースハブの公開鍵（X25519）で封じて送る（ECIES）。ニュースハブの設定で手で入れる道も残す。渡すのは鍵だけ。

## 6. 知識（Obsidian を発展させたもの）
- **知識カード**: 概要・技術の要素・用途・制約・関連の実装・条件別のベンチマーク・変化の履歴・根拠の論文と記事・**自分のメモ**（AI の部分と分けて、再分析で上書きしない）。
- **地図**: 点を押すと、関係する記事・性能の測定・関連の技術・過去の変化・公式の情報・未解決の問題・利用者のメモ。バックリンク。自動の関係は確かさと根拠つき（根拠の無い関係は確定として入れない）。
- **更新の履歴と矛盾**: 時点ごとの状態と根拠を残し、「過去 3 か月で AMD GPU 向けの推論はどう進んだか」「以前は非対応で最近対応したモデル」「公式と実測で評価の違うもの」に答えられるように。
- **Obsidian の書き出し**: 範囲を指定してまとめて Markdown（front matter・`[[リンク]]`）。常に書き出すことはしない（小さなファイルの書き込みを増やさない）。

## 7. トレンド
- 単純な頻度の上位だけにしない（「AI」「ゲーム」が並ぶだけになる）。点数（初期の配点）: 過去 30 日と比べた急上昇 25%・関わる独立したイベントの数 20%・独立した出どころの数 15%・新しさ 15%・利用者の関心 15%・一次情報の裏付け 10%。
- 方法: TF-IDF・c-TF-IDF（トピックの代表の語）・N-gram（「SSD Offload」のような複合語）・急上昇の検出（Kleinberg 法か z 値）・一緒に出る分析・トピックの分類（BERTopic の考え方を ControlDeck で。埋め込み → 次元を下げる → クラスタ → c-TF-IDF、増分）・新しい物の検出・イベントの検出・変化点の検出。
- 政治・経済は、話題性と事実の確かさを分けて扱い、報道の量を政策の評価に結び付けない。
- 表記ゆれ・略称の統合（「セキュリティトークン」「デジタル証券」「Security Token」「ST」は同じ概念、RWA は関連の概念として分ける）。

## 8. 検索と調査（ControlDeck との統合・優先度が高い）
- ControlDeck の Web 検索に、ニュースハブを追加の検索の提供元として入れる。ハイブリッド（全文・意味・物・つながり・時系列・数値・Web）を RRF で合わせ、必要なら reranker で並べ直す。LLM には関係の強い記事・知識カード・事実・数値だけを渡す。
- 調査の記録（テーマ・条件・出典・確かめた事実・比較表・結論・分からない点・生成物）をニュースハブへ送り、次の調査では前回からの変化を中心に調べる。
- 秘密の会話・特許の流れからの調査は送らない（ControlDeck の守りの規則のまま）。

## 9. 書き込みと読み込みを最小に（最重要の要件の 1 つ）
- **Write Coordinator**: すべての永続化（記事・履歴・集計・知識・ジョブの状態・画像・ログ・WAL の checkpoint・FTS のマージ・バックアップ）を 1 つの係が束ね、まとめて書く。各処理が勝手にディスクを書かない。
- 既定: 記事のまとめ書き 30 分ごと・バッファ 1,000 件 / 128MB・単一の書き手・WAL の checkpoint は保存の直後と保守の時間だけ（自動の checkpoint を切る）・索引の更新はまとめて・ログはメモリ（リングバッファ）・アクセスのログは既定で切・一時ファイルはメモリ優先・DB の最適化とバックアップは指定の時間・QNAP の上の LLM は既定で切。
- **お休みモード**（既定 切。開始・終了の時刻）: 休止中の動き「集め続けてメモリに一時保存」「集める・分析・保存をすべて休む」「集め続けて上限のときだけ一括で保存」から選ぶ。厳格な休止では、ログ・DB・checkpoint・画像・索引・ジョブ・バックアップを含め、アプリが原因の書き込みを止める。
- **保存が済んでいないデータを、保存済みとして扱わない**（API の答えにも「未保存」と分かる印。ControlDeck へ返す差分は保存済みのものだけ）。停電・強制終了ではメモリの分が消えうる（RSS に残っていれば次の取得で取り直せる）。手で書いた大事なメモは「すぐ保存」を選べる。
- 読み込みも減らす（目安）: 最新の一覧 128MB・SQLite のページのキャッシュ 256〜512MB・検索の結果 128MB・トレンド 64〜128MB・知識の地図 128〜256MB・取得のバッファ 128MB・ベクトルは規模に応じて。通常の上限 1.5〜2GB、ベクトル込みで 4GB を候補に実機で決める（QNAP のほかのアプリのために 16GB を占有しない）。
- **書き込みの診断**（メモリのリングバッファで）: 直近 24 時間の読み書きの量・回数・最終保存と次の予定・WAL の大きさ・未保存の件数・プロセスの I/O（/proc/self/io）・お休み中の書き込みの検出と、その処理の特定。アプリの書き込みと NAS 全体の書き込みを分けて測る。

## 10. 取得のエンジン
RSS 1.0・2.0・Atom の自動判別 / CSV と OPML の取り込み・書き出し / サイトからの RSS の発見 / **ETag・Last-Modified の条件付きの取得**（変わっていなければ本文を取らない）/ **更新の頻度に合わせた間隔（Adaptive Polling）** / 失敗・制限での間隔の延長（バックオフ）/ 重複の除去（URL・GUID・SimHash・意味の近さは ControlDeck）/ 出どころの種類（公式・報道・SNS・コミュニティ）/ 健全性の確認（止まった・XML の異常・失敗）。有料の記事・アクセスの制限・ロボット確認はすり抜けない。本文を保存できない記事は、取れる概要と元の URL だけ。

## 11. 画面
ホーム（今日読むべき 10 件・日次の要約）・ニュース（リーダー・検索・絞り込み・放送局ほか 5 デザイン）・イベント・ナレッジ（知識カード・技術の辞典）・グラフ（知識の地図）・トレンド（急上昇・ランキング）・タイムライン・ヒートマップ（分類 × 期間の情報の密度）・比較（モデル・GPU・価格・性能）・マトリクス（技術の関係・互換性）・調査・ウォッチリスト・メモ・生成物・管理（取得先・AI・保存と省電力・書き込みの診断）。すべての画面で、期間・分類・出どころ・言語・根拠の種類で絞り込める。大きなデータを一度に送らず、サーバーが必要な範囲だけ返す。未実装の機能を実装済みのように表示しない。

## 12. もっと価値を上げる機能
- **ベンチマークの比較**: 数値を測定の条件ごとに保存し、自分の環境（R9700・ROCm・使っているエンジン）に近いものだけを比べる。条件の違うものを平均しない。
- **組み合わせの発見**: 別々の記事の技術を関連付け、ControlDeck の既存の実装の改善の候補を提案（提案と動作確認済みは分けて持つ）。ControlDeck の「導入候補の検出」と同じ系統。
- **ウォッチリストと変化**: 監視のテーマ（ローカル LLM・推論エンジン・AMD GPU・音声 AI・ゲーム・日本株・ONDO・セキュリティトークン など）ごとに、「前回から何が変わったか」を出す。
- **意見の違い**: 政治・経済・株式・暗号資産では、公式の発表・報道・専門家の分析・企業の見解・コミュニティの反応・未確認の情報を分け、確かめた事実と並べる。

## 13. 守り
- 記事の中の命令を実行しない（プロンプトインジェクション）。ニュースの分析の係は最小の権限（ControlDeck の道具・コマンドを呼べない）。
- SSRF（私的な IP・リダイレクトの各段）・XML（外部の実体・過大な展開を禁止）・HTML（スクリプトを無効に）・API の認証（読み取りと書き込みを分ける）・AI の出力は JSON Schema で検査・事実と主張に出どころ・トランザクションと冪等性・整合性のある世代のバックアップ・著作権（保存と書き出しの対象を制御）。

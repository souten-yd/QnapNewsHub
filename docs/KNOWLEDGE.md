# 知識化・分析・大きなデータの設計（2026-11-24）

利用者「1 日 1000 件とか取れる場合、全部見るのは絶対に無理なので、オブシディアンみたいな感じでナレッジとして、詳細を分析して要素を取り出して、メモ・概要を残していく。各要素のつながりも明確にして、ノウハウマップのようなもの」「LLM 最新動向を調査して、のウェブ調査に合わせて、ニュースのデータを分析した結果から抽出できると、密度の濃い情報収集」「重要な単語の上位 10 件をトップのホットトピックスに」「情報分析ツール、ダッシュなどでインタラクティブなグラフ」「データベースの本体は QNAP。ControlDeck で使うデータは基本 QNAP から。画像生成したものは QNAP のデータベースに引き継ぐ」「数万〜数百万件。軽量の CPU で高速に抽出できるサーバー」「読み書きは最小限、メモリのキャッシュを存分に。書き込みはまとめて。夜間の指定した時間はお休みモード（メモリに保持して朝に書き込む）、入・切、既定は切」「アプリとアイコン、iOS のホーム画面のアイコンも」。

## 1. 取り出す（記事 → 要素）
- 下ごしらえ（30 件ずつ 1 回）の JSON に、記事ごとに次を足す（呼び出しの回数は増やさない）:
  - `entities`: 出てくる物 `[{"name": 表記, "type": model|software|org|person|tech|product|game|place|other}]`（最大 8）
  - `facts`: その記事で分かったこと `[{"about": 物の名前, "kind": release|benchmark|price|date|claim|other, "text": 日本語の短い文, "value": 数値や版（あれば）}]`（最大 5）
- 名寄せ: 表記ゆれ（大文字小文字・記号・「Llama 3.1」と「llama3.1」・日本語と英語）を正規化のキーでまとめ、別名の表に持つ。迷うものは別々にしておき、ノートの書き直しのときに LLM に「同じ物か」を聞く（1 晩にまとめて 1 回）。
- 取り出しの結果は記事の版（抜粋の hash）に結び付け、抜粋が変わったら取り直す。

## 2. 物ごとのノート（Obsidian のように）
- 物ごとに 1 枚: 名前・別名・種類・はじめて出た日・関わった記事の年表（日付と見出しと出典）・分かったこと（facts を新しい順、重複をまとめる）・関係する物（下のつながり）・概要（数行）。
- 概要の書き直しは **毎晩 1 回、その日に新しい記事が付いた物だけ**、まとめて（1 回の呼び出しで 10 物ずつ）。無料の LLM、または ControlDeck がつながっていれば CPU の Gemma に任せる。
- ノートは Markdown で書き出せる（Obsidian の vault の形: 物ごとの .md、`[[関係する物]]` のリンク、記事は出典の URL）。書き出しは利用者の操作で（または毎週）。

## 3. つながり（ノウハウの地図）
- 同じ記事に一緒に出た物の組を数え、偶然より多い組だけを辺にする（PMI か、期待値との比が 2 以上・一緒に出た回数 3 以上）。辺の重みは期間（7 日・30 日・全体）ごとに集計の表に持つ。
- 物のまとまり（話題の塊）を、辺の重みで分ける（Louvain 法など、数千の物なら CPU で 1 秒以内）。毎晩 1 回。
- 画面: 物を点、つながりを線にした地図（拡大・絞り込み・期間・種類）。点を押すとノートへ。

## 4. ホットトピック（LLM なし）
- 物・話題の語・見出しの語（英語は小文字の語と 2 語の組、日本語は LLM の取り出した語と見出しのカタカナ・英数の語）ごとに、日ごとの出現の数を集計の表に持つ。
- 今日（直近 24 時間）の数を、過去 7〜28 日の平均と散らばりと比べ（z 値と増えた割合、少数の過大評価を抑える補正）、急に増えたものを上位 10 件。**新しく出てきた物**（過去に無い）は別の枠。
- 分野ごと・チャンネルごとのホットトピックも同じ表から出す。画面の一番上とホームのカードに。1 時間に 1 回計算してメモリに置く。

## 5. 調査と組み合わせる（ControlDeck の AI アシスタント）
- ControlDeck の Web 調査（Deep Research を含む）の道具に「ニュースハブの知識」を足す: 問いの語に合う物のノート・ホットトピック・関係する記事（全文検索と、ControlDeck の RAG）を、Web の結果と並べて根拠として渡す。出典はニュースハブの記事の元の URL。
- ニュースハブは公開の情報だけ。秘密の会話・特許の流れからの問いは渡さない（ControlDeck の守りの規則のまま）。

## 6. 分析の画面（ダッシュボード）
- 話題の推移（日ごとの線・積み上げ）、物の地図、ホットトピックの表、取得先ごとの量と質（記事の数・下ごしらえの成功・画像の有無）、分野ごとの勢い、期間の比較（今週と先週）。
- グラフは軽い部品（uPlot か ECharts のどちらか、build の大きさで選ぶ）を遅延読み込み。地図は sigma.js（WebGL・数千の点）か cytoscape.js。集計の表だけを読むので、記事が数百万件でも画面は速い。

## 7. データの本体は QNAP
- ControlDeck は記事・ノート・ホットトピックを基本的にニュースハブから受け取る（同期の API・前回からの分だけ・必要な分野だけ）。
- **ControlDeck で生成した画像はニュースハブへ送る**: 同期のトークンに「画像を送る」権限だけを足し、`PUT /api/v1/sync/items/{id}/image`（webp・上限 512KB・画像の形を検査）。ニュースハブは画像を置き場に保存し、記事の image_url をニュースハブの URL に（「AI 生成のイメージ」の印つき）。ControlDeck のリーダーの要約・訳も同じように送れる（ニュースハブの画面で読める）。

## 8. 大きなデータを非力な CPU で速く
- **SQLite（WAL）のまま**、索引をきちんと: 記事（取得先・日時・正規化の URL の一意）、物（正規化のキーの一意）、記事と物の結び付き（物→日時の索引）。
- **集計の表**: 日ごとの「物の数・語の数・取得先の数・分野の数」、期間ごとの「物の組の数」。画面とホットトピックは集計の表だけを読む。集計は書き込みのまとめと一緒に、増えた分だけ足す。
- **全文検索**: FTS5（見出し・概要・取り出した要素）。古い記事（既定 1 年より前）は本文の抜粋を圧縮して残し、索引は見出しと概要だけ。
- **メモリ**: SQLite の読み込みのキャッシュを大きく（既定 1GB、設定で変える・mmap）、ホーム・ホットトピック・地図・ダッシュボードの答えをメモリにキャッシュ（データが変わったときだけ作り直す）。16GB の機械を想定し、既定の合計の上限 2GB。
- **数百万件の目安**: 記事 1 件あたり 2〜4KB（索引込み）で 100 万件 3〜4GB。集計の表で画面は数十 ms。数百万件で遅くなる集計は、DuckDB に毎晩書き出して分析の画面だけそちらで、を 2 段目の案として残す（測ってから決める）。

## 9. 書き込みを最小に・お休みモード
- **まとめて書く**: 取得の 1 回で取った記事・履歴・画像の URL を、1 つのトランザクションで書く（取得の 1 回に 1 回）。下ごしらえの結果も 1 バッチ（30 件）に 1 回。集計の表の足し込みは 1 時間に 1 回。WAL の checkpoint は書き込みの後にまとめて（常に小さく書き続けない）。
- **お休みモード**（入・切、既定は切。時間帯を設定）: その時間は SQLite に書かず、取った記事などをメモリの列に溜める（上限 例 5 万件・256MB。超えたら一度にまとめて書く）。時間帯が終わったら一度に書く。読み（画面）はメモリの列も合わせて見せる。**停電・強制終了ではメモリの分が消える**ことを設定の画面に書く（記事は次の取得で RSS に残っていれば取り直せる）。
- お休み中は下ごしらえ・まとめ・集計・ノートの書き直しも止める（朝にまとめて）。

## 10. アプリとアイコン
- ニュースハブのアイコン（SVG を元に、16・32・180〔apple-touch-icon〕・192・512 の PNG、マスク可能な版）。色は放送局のデザイン（暗い地・黄）。
- PWA: `manifest.webmanifest`（name「ニュースハブ」・short_name・display standalone・theme_color・icons）、`apple-touch-icon`、`apple-mobile-web-app-capable`・status bar・Safe Area。iPhone のホーム画面に追加すると全画面のアプリとして開く。
- QPKG のアイコン（QNAP の App Center 用の 64・80 の PNG と灰色の版）も同じ元から作る。
